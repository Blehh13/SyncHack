## What changes for users

A sync run whose job exhausted its retries stayed at `PROCESSING` forever, and the error was only visible in the Inngest dashboard. `FAILED` existed in the schema but nothing wrote it.

Now an Inngest `onFailure` handler sets the run to **`FAILED`** and stores the failure in `details`:

```json
{
  "failedAt": "2026-09-16T06:10:00.000Z",
  "error": { "name": "Error", "message": "Failed to fetch commit diff: Not Found", "truncated": false },
  "inngestRunId": "01JABCDEF"
}
```

So a failed run can be diagnosed from the database alone.

## Implementation
- `src/lib/sync-status.ts`: `buildFailureDetails(error, runId)`, which handles non-`Error` values and truncates messages at 2000 characters, flagging when it does
- `src/inngest/functions.ts`: `onFailure` on `process-push-event`, reading the original event's `syncLogId` from the failure payload
- `README.md`: the run lifecycle now lists `FAILED`
